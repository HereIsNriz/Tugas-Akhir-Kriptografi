# Panduan Implementasi: SHA-256

## 1. Konsep Dasar
SHA-256 adalah fungsi hash kriptografi satu arah yang menghasilkan *digest*
256 bit (32 byte) dari data berukuran berapa pun [3]. Sifatnya: deterministik,
satu arah (*preimage resistant*), perubahan 1 bit input mengubah output secara
drastis (*avalanche effect*), dan sulit ditemukan tabrakan (*collision
resistant*) [3].

Di aplikasi ini SHA-256 dipakai di tiga tempat:
1. **Hash entri diary** untuk deteksi modifikasi.
2. **Penurunan seed LFSR** dari password.
3. **Hash blok** pada blockchain + proof of work.

## 2. Arsitektur & Prinsip Kerja
- Ukuran blok: 512 bit (64 byte), state: 8 word × 32 bit ($a,b,c,d,e,f,g,h$) [3].
- **Padding:** tambahkan bit `1`, lalu bit `0` secukupnya, lalu panjang pesan
  asli (64 bit big-endian) sehingga total kelipatan 512 bit [3].
- **Message schedule:** 16 word pertama ($W_0..W_{15}$) dari blok, sisanya
  ($W_{16}..W_{63}$) diturunkan dengan rumus [3].
- **Compression:** 64 putaran memakai konstanta $K_t$ [3].
- Nilai awal hash ($H_0..H_7$):
  `6a09e667 bb67ae85 3c6ef372 a54ff53a 510e527f 9b05688c 1f83d9ab 5be0cd19`

## 3. Rumus & Operasi
- $\text{Ch}(e,f,g) = (e \wedge f) \oplus (\neg e \wedge g)$
- $\text{Maj}(a,b,c) = (a \wedge b) \oplus (a \wedge c) \oplus (b \wedge c)$
- $\Sigma_0(a) = \text{ROTR}^2(a) \oplus \text{ROTR}^{13}(a) \oplus \text{ROTR}^{22}(a)$
- $\Sigma_1(e) = \text{ROTR}^6(e) \oplus \text{ROTR}^{11}(e) \oplus \text{ROTR}^{25}(e)$
- $\sigma_0(x) = \text{ROTR}^7(x) \oplus \text{ROTR}^{18}(x) \oplus \text{SHR}^3(x)$
- $\sigma_1(x) = \text{ROTR}^{17}(x) \oplus \text{ROTR}^{19}(x) \oplus \text{SHR}^{10}(x)$
- **Message schedule:** $W_t = \sigma_1(W_{t-2}) + W_{t-7} + \sigma_0(W_{t-15}) + W_{t-16}$
- **Tiap putaran:**
  $$T_1 = h + \Sigma_1(e) + \text{Ch}(e,f,g) + K_t + W_t$$
  $$T_2 = \Sigma_0(a) + \text{Maj}(a,b,c)$$
  $$h=g,\ g=f,\ f=e,\ e=d+T_1,\ d=c,\ c=b,\ b=a,\ a=T_1+T_2$$
  (semua penjumlahan modulo $2^{32}$)

## 4. Contoh Perhitungan Manual
- **Input:** `"abc"` (ASCII: `61 62 63`)

### Padding (1 blok 512 bit)
```text
W0  = 61626380   (61 62 63 + bit '1' = 0x80)
W1..W14 = 00000000
W15 = 00000018   (panjang pesan = 24 bit = 0x18)
```

### Putaran ke-0 (t = 0)
Nilai awal: a=6a09e667, b=bb67ae85, c=3c6ef372, d=a54ff53a, e=510e527f,
f=9b05688c, g=1f83d9ab, h=5be0cd19. $K_0$ = 428a2f98, $W_0$ = 61626380.

```text
Σ1(e)  = 3587272b
Ch     = 1f85c98c
T1     = h + Σ1 + Ch + K0 + W0 = 54da50e8
Σ0(a)  = 0ce20b47e → dipotong 32 bit = ce20b47e
Maj    = 3a6fe667
T2     = Σ0 + Maj = 08909ae5
a_baru = T1 + T2 = 5d6aebcd
e_baru = d + T1  = fa2a4622
```

State setelah putaran 0:
```text
a=5d6aebcd b=6a09e667 c=bb67ae85 d=3c6ef372
e=fa2a4622 f=510e527f g=9b05688c h=1f83d9ab
```

### Hasil akhir setelah 64 putaran + penjumlahan dengan $H_0..H_7$
```text
SHA-256("abc") =
ba7816bf 8f01cfea 414140de 5dae2223 b00361a3 96177a9c b410ff61 f20015ad
```

## 5. Implementasi pada Aplikasi
Aplikasi memakai `hashlib.sha256` (implementasi manual tidak diperlukan).

- Helper `sha256(s)` — `diary_app.py:289-290`:

  ```python
  hashlib.sha256(s.encode()).hexdigest()
  ```

### (a) Hash entri diary
Saat entri disimpan, yang di-hash adalah **ciphertext** (judul dan isi yang
sudah terenkripsi), bukan plaintext — `diary_app.py:884`:

```python
tambah_blok(f"entry:{cur.lastrowid}:{sha256(j_enc + i_enc)}", self.user_id)
```

Hash ini disimpan di kolom `data` pada tabel `blocks`, **bukan** di tabel
`entries`. Saat verifikasi, aplikasi menghitung ulang
`sha256(judul_enc + isi_enc)` dan membandingkannya (`diary_app.py:332`).

### (b) Seed LFSR
`diary_app.py:142`:

```python
seed = int.from_bytes(hashlib.sha256(password.encode()).digest()[:2], "big")
```

Hanya 2 byte pertama yang dipakai (16-bit), dengan pengganti `0xACE1` bila nol.

### (c) Hash blok blockchain
`diary_app.py:293-294`:

```python
def hitung_hash(idx, ts, data, prev, nonce):
    return sha256(f"{idx}|{ts}|{data}|{prev}|{nonce}")
```

Perhatikan: hash blok memakai **string dengan pemisah `|`**, bukan JSON, dan
**menyertakan timestamp**. Detail ada di `BLOCKCHAIN_POW.md`.

## 6. Catatan Keamanan
- Jangan memakai SHA-256 langsung untuk hash password; gunakan PBKDF2
  (`PBKDF2.md`).
- SHA-256 adalah fungsi hash, bukan enkripsi; hasilnya tidak dapat dibalik.
- Perubahan sekecil apa pun pada input mengubah seluruh digest.
